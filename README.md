# BBB Companion

Локальная утилита для Windows: расписание BBB, до 15 изолированных подключений, режим «Только слушать», повторение разрешённых массовых реакций и выход при массовом уходе участников.

## Скачать

Готовые Windows-сборки доступны в [GitHub Releases](https://github.com/Ysherka/bbb-faker/releases/latest). Скачивайте ZIP-архив целиком: EXE использует комплектные файлы и Chromium.

Пример `config.example.json` содержит вымышленные имена и демонстрационную ссылку. Для работы укажите собственную ссылку на комнату.

**Версия 0.2.1:** до 15 подключений, один экземпляр Chromium на предмет и управление окном предмета. Сохраняются недельная таблица, двухнедельное расписание, трей, автозапуск и передача данных. Поддержка конкретного сервера BBB проверяется на реальной лекции; автоматические проверки используют локальные страницы.

## Новое в 0.2.1

- Максимум 15 одновременных подключений суммарно по приложению; в одно занятие можно назначить до 15 людей. Меньший предел задаётся в настройках.
- Один экземпляр Chromium на каждый активный предмет (по ID предмета), внутри — отдельный BrowserContext каждого человека с собственными cookies и хранилищем. Разные предметы, даже с одной ссылкой, используют разные экземпляры браузера. Chromium сам создаёт служебные процессы и процессы рендеринга вкладок.
- В блоке **Браузеры предметов** одна кнопка **Показать браузер / Скрыть браузер** на предмет. Для просмотра показывается контекст одного человека; остальные окна скрыты и не воспроизводят звук. Текущий человек указан в блоке предмета. Вход в BBB и режим слушателя сохраняются при переключении.
- Выход человека закрывает только его контекст. Если открыт его контекст, просмотр переходит к следующему подключению того же предмета. Последний выход закрывает браузер предмета, остальные предметы продолжают работу.
- Конфигурация обновляется до `version: 2`, предыдущий файл сохраняется в `config.backup.json`. Прежний стандартный лимит 5 автоматически становится 15; меньшие настроенные пределы сохраняются. В конфигурации версии 2 можно явно установить любой лимит от 1 до 15. Схема переносимого файла импорта/экспорта остаётся версии 1.

## Новое в 0.2.0

- Повторение **раз в две недели**: выберите дни недели и опорную дату. Неделя с этой датой активна, следующая пропускается. Отсчёт ведётся от понедельника; даты до опорной тоже чередуются. Ограничить период можно полями «Действует с / до».
- В разделе **Расписание → Неделя** доступны переходы между неделями, фильтр по человеку и редактирование прямо из таблицы. Пустая ячейка создаёт разовое занятие на выбранную дату; повторение можно изменить в форме. Карточка открывает всё правило расписания. Выключенные занятия видны в режиме «Список».
- EXE запускается **в трее**, без консоли и автоматического открытия панели. Двойной щелчок по значку или пункт «Открыть настройки» открывает веб-интерфейс. Закрытие вкладки не завершает приложение.
- В **Настройках** можно включить запуск при входе в Windows для текущего пользователя. Права администратора не нужны. После перемещения приложения выключите и включите автозапуск, чтобы обновить путь. Windows может запускать программы с задержкой после входа.
- В 0.2.0 добавлены показ и скрытие браузера без повторного входа. В 0.2.1 управление перенесено на предмет и применяется к группе контекстов.
- **Расписание → Импорт и экспорт** позволяет передать людей, предметы и занятия в одном JSON-файле. Можно экспортировать отдельные разделы; необходимые расписанию люди и предметы включаются автоматически. Импорт сначала показывает результат, затем добавляет данные либо заменяет все три раздела. Совпадающие записи пропускаются, конфликтующие идентификаторы переименовываются с сохранением связей. Настройки этого компьютера, автозапуск и журнал не передаются. Активные подключения продолжаются со своими сохранёнными параметрами.

Полная конфигурация из 0.1.1 и 0.2.0 читается без ручной конвертации; у старых занятий по умолчанию `interval_weeks: 1`.

Для сохранения настроек при обновлении завершите старое приложение и перенесите копию его папки `data` рядом с новым EXE. ZIP-архив распространяется без пользовательских данных. При запуске могут восстановиться незавершённые актуальные занятия согласно сохранённому состоянию.

## Запуск готовой сборки

1. Распакуйте ZIP-архив Windows-сборки 0.2.1 целиком в доступную для записи папку.
2. Запустите `BBBCompanion.exe`. Через значок в трее откройте панель по адресу `http://127.0.0.1:8765`.
3. Добавьте людей, предметы и занятия. Время расписания — Самара.
4. Включите расписание кнопкой на главном экране. При первом запуске оно выключено.

Python и отдельная установка Chromium для полной сборки не нужны. Приложение работает, пока запущен EXE; компьютер должен оставаться включённым и не переходить в сон. Для завершения используйте меню трея или кнопку в панели. Чтобы открывать панель сразу, запускайте с `--open-browser`; для работы без трея предусмотрен `--no-tray`.

Данные создаются в папке `data` рядом с EXE:

- `config.json` — настройки, доступные также из панели;
- `config.backup.json` — предыдущая версия настроек;
- `state.sqlite3` — состояние занятий и журнал;
- `diagnostics` — снимки страницы и перечни DOM-элементов при ошибках/по ручной команде.

В новой диагностике также сохраняются `page-state.json` с результатами распознавания и `chat-sample.html` с ограниченной выборкой разметки чата. Эти файлы могут содержать имена и текст общего чата.

Для переноса на другой компьютер сначала завершите приложение, затем скопируйте всю папку, включая `data`. Это сохраняет историю и сведения о выполненных выходах. Два экземпляра с одной папкой данных одновременно не запускаются. Для указания другого места хранения: `BBBCompanion.exe --data-dir "D:\BBB-data"`.

## Локальная проверка без лекции

На экране «Сейчас» раскройте «Локальная демонстрация»:

1. Запустите от одного до 15 профилей. Они подключаются только к модели комнаты внутри приложения; внешние сайты не открываются.
2. Нажмите «Приветствия» или «Плюсы»: появятся сообщения от шести внешних авторов.
3. В журнале появится волна и результаты ответов профилей.
4. Уменьшите число внешних участников с 40 до 10. Через 30 секунд подтверждения профили выйдут.
5. Кнопки «Обрыв» и «Восстановить связь» позволяют проверить восстановление без ложного массового выхода.

Пороги работают в реальном времени. Для повторной волны одной группы требуется тишина этой группы в течение двух минут. Демонстрация использует текущие настройки приложения и занимает обычные слоты подключений.

## Первая проверка на настоящем BBB

1. Настройте один профиль и одно актуальное занятие.
2. В «Настройках» включите режим наблюдения без отправки сообщений. При необходимости снимите флажок скрытия окон браузера.
3. Включите расписание в подходящее время. Приложение подключается и посреди занятия, если оно ещё идёт по расписанию.
4. Убедитесь в BBB, что имя верное и отображается режим слушателя. Сравните число участников и проверьте чтение новых сообщений по событиям волн в журнале.
5. При проблеме сохраните диагностику из карточки подключения. Путь появится в журнале. Снимки могут содержать имена и чат занятия, храните их локально.
6. После подтверждения чтения интерфейса можно отключить режим наблюдения для следующих подключений и проверить несколько профилей.

Изменения расписания и параметров не меняют уже запущенные подключения. Чтобы применить новые параметры к текущей проверке, потребуется новый экземпляр занятия. Ручной выход из старого экземпляра запоминается и не отменяется перезапуском.

## Расписание и JSON

Пример структуры находится в `config.example.json`. Полный JSON с действующими значениями можно экспортировать, импортировать и редактировать кнопкой `JSON` в панели. При ручном редактировании `data/config.json` остановите приложение.

- Дни недели: `0` — понедельник, `6` — воскресенье.
- Для еженедельного занятия используется `weekdays`, для разового — `date`; одновременно их указывать нельзя.
- Для занятия раз в две недели добавьте `"interval_weeks": 2` и `"anchor_date": "2026-10-26"`. Все выбранные дни недели чередуются относительно недели с этой датой. Для разового занятия допустим только интервал 1.
- `excluded_dates` отменяет отдельные исходные даты.
- `moves` переносит конкретный экземпляр: `original_date`, новая `date`, `start`, `end`.
- Постоянные `id` не меняйте при переименовании записей: они связывают расписание и историю.
- Пересечения для одного человека разрешаются по порядку начала: второе занятие ожидает свободного профиля, пока остаётся актуальным. Конфликт записывается в журнал.
- При достижении установленного лимита подключений (по умолчанию 15) дополнительные занятия ожидают свободного слота.

Настройки проверяются перед сохранением. При ошибке первоначального чтения JSON исходный файл сохраняется, автоматическое подключение блокируется, а ошибка показывается в панели.

## Правила поведения

- Чат: за 60 секунд минимум пять разных внешних авторов и минимум 60% от всех писавших внешних авторов должны отправить разрешённую реакцию одной группы.
- Варианты приветствия, прощания и плюсов объединяются по заданным группам. Текст выбирается среди реально увиденных разрешённых вариантов.
- Собственные управляемые профили исключаются из подсчёта. История при входе и восстановлении не вызывает ответов.
- На волну допускается один ответ на профиль. При неопределённом результате отправки слепой повтор не выполняется.
- Выход: за последние 120 секунд ушло минимум 60% внешних участников, и численность не восстановилась выше порога за 30 секунд.
- Если внешние участники уже были, а затем остались только наши профили, проверка пустой комнаты длится 15 секунд.
- Собственный обрыв или отсутствие надёжного счётчика приостанавливают выводы по численности.
- Явное сообщение BBB о завершении преподавателем вызывает выход независимо от числа оставшихся участников.
- Плановое окончание не вызывает немедленного выхода: предельное пребывание по умолчанию ограничено окончанием плюс 60 минут.
- Ручной и автоматический выход сохраняются для конкретного экземпляра занятия.

При отсутствии устойчивых идентификаторов авторы в DOM определяются по отображаемым именам; совпадающие имена могут уменьшать число распознанных авторов. Селекторы текущего официального клиента BBB требуют проверки на версии университета. При невозможности надёжно прочитать счётчик выход по численности приостанавливается, предупреждение появляется в журнале.

## Разработка

Из корня проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m bbb_companion
```

Альтернативный запуск после установки — `run.bat`.

Точные версии проверенного окружения находятся в `requirements-dev.lock`. Для воспроизведения можно установить их командой `python -m pip install -r requirements-dev.lock` внутри `.venv`.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
.\.venv\Scripts\python.exe scripts\smoke_exe.py --legacy
.\.venv\Scripts\python.exe scripts\package_release.py
```

Браузерный тест использует только локальную HTML-страницу. Он проверяет прохождение формы, выбор аудио, исключение истории, чтение новых сообщений, отправку и изоляцию контекстов. Это не заменяет проверку настоящего сервера BBB.

Панель привязана к `127.0.0.1`. Команды изменения защищены токеном текущего запуска. Удалённое управление и Docker в эту версию не входят.
